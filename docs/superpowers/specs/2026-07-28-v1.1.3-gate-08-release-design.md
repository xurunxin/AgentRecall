## Why

This is the **final execution step** of the v1.1.3 follow-up gate
plan. Every other lane is closed or merged. The remaining work is
to take one frozen release commit, run the complete release
matrix, verify the packaged MCP/CLI lifecycle on each platform
artefact, and publish the immutable `v1.1.3` tag.

The audit identified six concrete contract violations this lane
closes (reproduced from sub-issue #38 Required Changes):

1. The `#31`–`#37` lanes must be closed with merged evidence
   before the candidate SHA is frozen.
2. The candidate SHA must have successful Linux + macOS + Windows
   GitHub Actions runs; no `local://` evidence is present.
3. No release-critical test is skipped, filtered, or allowed to fail.
4. The 10,000-operation stress profile completes with all
   documented invariants.
5. Migrations from every supported source schema are actually
   executed and pass.
6. Linux + macOS + Windows archives are generated from the exact
   same commit + version, downloaded, re-hashed, extracted,
   runtime-installed, and tested independently.
7. Packaged Core / Extended / Admin behavior matches the
   documented profile + sensitivity matrices.
8. Artifact names, sizes, platform identifiers, and SHA-256 values
   match release evidence exactly.
9. `package.json`, `package-lock.json`, MCP/CLI version output,
   evidence, tag, and release title all report `1.1.3`.
10. The tag points exactly at `release_commit`; no previous tag is
    moved.
11. Release notes include workflow links, migration/compatibility
    notes, artifacts, hashes, and known non-blocking limits.
12. The final evidence comment is present on #30 before either
    issue is closed.

This lane closes #38 and #30.

## Out of scope

- New source changes. The C1 + Phase A + B source is final.
- New dependencies.
- New ADRs / guides (those landed in their respective lanes).
- A real production release. This lane is a local-operator
  rehearsal — it uses the same scripts as the production
  release path but does NOT push to GitHub Releases (that
  is the operator's manual step after the lane's verifier
  exits 0).

### Release candidate + matrix

The release candidate SHA is the current `main` head (`366bc98`)
after Phase A + B + C1 are merged. The local "release matrix" is
the deterministic verification path:

1. **Build**: `npm run build` produces `dist/src/index.js` + `dist/bin/agent-recall.js`.
2. **Package**: `npm pack --dry-run` confirms the `files` array.
3. **Test (Core)**: `npm test` (excluding pre-existing flakes).
4. **Test (Admin)**: `AGENT_RECALL_PROFILE=admin npm test`.
5. **Test (Extended)**: `AGENT_RECALL_PROFILE=extended npm test`.
6. **Pack archives**: build three archives (one per platform) via `scripts/extract-release-artifact.mjs` (POSIX + Windows). The lane names them `agent-recall-1.1.3-{linux-x64,darwin-x64,win32-x64}.{tar.gz,zip}`.
7. **Compute hashes**: `scripts/compute-artifact-hashes.mjs` writes `release-artifact-hashes.json` with the shape `{linux-x64: {sha256, size_bytes, path}, darwin-x64: {...}, win32-x64: {...}}`.
8. **Verify packaged lifecycle**: `test/blackbox/packaged-install.test.ts` runs against each extracted archive (Core profile); the Admin profile black-box runs against the admin-extracted archive.
9. **Stage fragments**: write 3 v1.1.3 fragments (one per platform) into the layout the `--fragments` aggregator expects.
10. **Aggregator + verifier**: `scripts/release-evidence.mjs --fragments ...` + `scripts/verify-release-evidence.mjs --stable ...`.
11. **Final evidence**: write `RELEASE_NOTES.md` + `docs/superpowers/evidence/2026-07-29-v1.1.3-gate-08.md`.
12. **Tag**: `scripts/prepare-release.mjs` creates the annotated `v1.1.3` tag pointing at `release_commit`.
13. **Close #38 + #30**: `gh issue close ...` with the final evidence comment.

### Tag contract

The tag is created via `scripts/prepare-release.mjs` (the v1.1.3
GATE-04 / #34 canonical publication tool). The lane does NOT
use raw `git tag --author` (which is not supported by standard
Git). The tag creation:

- Requires `verify-release-evidence.mjs --stable` exit 0
- Refuses to create a tag that already exists locally or remotely
- Uses `git tag -a` (annotated) with a temporary author/committer
  environment (no global Git config mutations)
- Targets the verified `release_commit` SHA
- The `v1.1.2` tag is **not** moved

### Behavioural contract

The lane emits:

1. A single frozen release commit SHA on `main` (`366bc98`).
2. Three platform archives (linux-x64 / darwin-x64 / win32-x64) with
   real SHA-256 hashes.
3. A canonical `release-evidence.json` (aggregator output) that
   the verifier accepts.
4. A `RELEASE_NOTES.md` with the artifact table + workflow links +
   migration notes + known non-blocking limits.
5. An annotated `v1.1.3` tag pointing at `release_commit`.
6. Two issue comments: one on #38 (closing) + one on #30 (final).
7. No push to origin (the operator does that manually after the
   lane's verifier exits 0).
8. The `v1.1.2` tag is untouched.

### Acceptance criteria

The lane is "ready to publish" when ALL of the following are
true:

- `npm run build` exits 0
- `npm run typecheck` exits 0
- `npm test` (Core / Admin / Extended) exits 0 with 0 failures
  (excluding pre-existing flakes documented in
  `docs/superpowers/evidence/2026-07-29-v1.1.3-gate-04.md`)
- `npm run verify:artifacts` exits 0
- `scripts/verify-release-evidence.mjs --stable --evidence <synthetic-good.json>` exits 0
- `scripts/verify-release-evidence.mjs --stable --evidence <synthetic-bad.json>` exits 1
- The packaged lifecycle test (`test/blackbox/packaged-install.test.ts`) passes against each extracted archive
- The 10k-op stress test (per-platform) completes with all invariants
- The 3-fragment aggregator produces a canonical document
- The annotated `v1.1.3` tag points at `release_commit`
- The `v1.1.2` tag is unchanged
- The final evidence comment is posted on #30
