## Why

The v1.1.2 release-evidence pipeline lets a partial / placeholder
/ fabricated-evidence pass be presented as a valid publication:
inconsistent platform vocabularies (`windows-x64` vs `win32-x64`)
+ array-as-checksum shapes + local fallback paths + hard-coded test
totals. The current gate either fails noisily OR — when the
fabrication is well-formed — succeeds silently with bogus
artifacts.

The audit identified seven concrete contract violations
(reproduced here from `sub-issue #34` Required Changes):

1. Workflow artifacts use `windows-x64` while evidence
   validators require `win32-x64`.
2. `artifacts` and `sha256_checksums` are both assigned the same
   array; the verifier requires checksums to be an object.
3. Local fallback evidence can report `local://` jobs/workflows
   as successful release proof.
4. Test totals + migration summaries can be generated from
   hard-coded defaults rather than actual job outputs.
5. The preparation path may continue when verified release
   evidence is absent.
6. Stable-release mode does not reject `local://` URLs, missing
   GitHub workflow URLs, zero-duration placeholder jobs, or
   hard-coded test totals.
7. The schema isn't validated; the aggregator can consume
   truncated / duplicate / mismatched sets without failing.

This lane (#34) closes all seven + tightens the version
metadata + tag tooling (#35) + the deterministic test
orchestration (#36, the parallel B2 lane).

## Out of scope

- Tag/version reproducible publication (covered by #35 / AB).
- Test orchestration split (covered by #36).
- New dependencies. Stdlib only + the existing release scripts.
- Schema migration. The existing v1.1.2 `user_version` stays.

## What this design ships

### File-level delta

| Path | Change |
|------|--------|
| `scripts/release-evidence.mjs` | NEW canonical platform vocabulary `CANONICAL_PLATFORMS = ["linux-x64", "darwin-x64", "win32-x64"]`. The aggregator parses + canonicalises the workflow matrix `platform` before recording. Evidence loader reads `release-evidence.schema.json` (zod) and rejects: local URLs in stable mode, missing GitHub URLs, zero-duration placeholders, hard-coded test totals, empty/mismatched/duplicate artifact sets, checksum entries that do not match downloaded bytes (via a new `verifyChecksumAgainstArtifact(path, expectedSha256)` helper). |

Returns exit 0 on success; non-zero with stable reason codes on failure. |

### Public surface delta

| Surface | Before (v1.1.2) | After (#34) |
|---------|------------------|-------------|
| `scripts/verify-release-evidence.mjs` CLI | ad-hoc field checks; permissive | strict schema + fail-closed invariants; stable reason codes on failure |
| `release-evidence.json` schema | unreleased; permissive | versioned; canonical platforms only; checksums are an object; no `local://` URLs in stable mode |
| `prepare-release.mjs` | may proceed without verified evidence + may continue on placeholder evidence | requires verified candidate SHA + verified evidence + tag-only workflow success |
| `release-candidate.yml` matrix platform vocabulary | arbitrary; commonly `windows-x64` | canonical only |
| `release.yml` evidence verifier | permissive | strict; rejects `local://`, zero-duration placeholders, hard-coded test totals |

### Behavioural contract

In **stable-release mode**:

- `verify-release-evidence.mjs` exit 0 iff every field passes. Stable
  reason codes (every failure mode has a stable string code):
  - `LOCAL_URL_FORBIDDEN` — any `*_url` field contains `local://`
  - `PLATFORM_NOT_CANONICAL` — any artifact's platform is not in
    `CANONICAL_PLATFORMS`
  - `CHECKSUM_TYPE_INVALID` — `sha256_checksums` is not an object
  - `CHECKSUM_BYTES_MISMATCH` — `sha256_checksums[path] !== sha256(file_bytes)`
  - `CANDIDATE_SHA_MISMATCH` — `candidate_sha !== release_commit`
  - `DURATION_PLACEHOLDER` — any job has `duration_ms === 0`
  - `TEST_TOTALS_FROM_CONSTANT` — `test_summary.totals_from === "constant"`
  - `MISSING_GITHUB_JOB_URL` — any ci_job lacks `https://github.com/` URL
  - `EMPTY_ARTIFACTS` / `DUPLICATE_ARTIFACTS` / `MISMATCHED_PLATFORMS`
  - `SCHEMA_INVALID` — any field missing or wrongly typed (zod error)

In **local-development mode** (`AGENT_RECALL_DEV_MODE=1` or per an env
escape hatch), the verifier tolerates `local://` URLs and constant
test totals but still enforces the canonical vocabulary + checksum
match. The flag is logged prominently and excluded from any CI /
release run by default.

### Cross-cutting invariants

- The verifier never writes to `release-evidence.json` — it only
  reads.
- `prepare-release.mjs` requires the verifier exit 0 on the
  candidate commit before creating or moving any tag.
- `release.yml` (tag-only) re-runs the verifier with the
  same evidence, asserting SHA equality between
  `release_commit` and `head_sha` at the tag.
- The verifier is the canonical authority on the schema; the
  aggregator trusts it for redaction / canonicalisation only.

### Tests + TDD ordering

1. **RED** — `p3-release-evidence.test.ts` with the
   schema-level tests. Existing release-script tests stay.
2. **GREEN** — implement `release-evidence.schema.json` (zod
   shape) + the aggregator's canonicalisation + the verifier's
   fail-closed invariants.
3. **RED+GREEN** — `p3-release-evidence-negative.test.ts`
   (one fixture per reject reason).
4. **RED+GREEN** — `p3-release-evidence-aggregator.test.ts`
   (3-fragment happy path + missing-fragment + checksum
   mismatch).
5. **CI wiring** — update `release-candidate.yml` +
   `release.yml` to use the canonical vocabulary and call the
   verifier with stable-mode flags.
6. **Final** — `npm test` + typecheck + build + verify:artifacts
   on the existing surface (B1 changes are scripts, not source).

### Regression risk

The verifier replaces ad-hoc field checks. The risk is rejecting
existing valid evidence that contains a non-canonical token. The
mitigation: a one-time migration script (`scripts/migrate-evidence-to-canonical.mjs`,
NEW for this lane) reads existing v1.1.2 evidence documents and
canonicalises the platform vocabulary before the new verifier
runs. The migration is a one-shot operator action — NOT a
release-blocker.

The aggregator's three-fragment merge is the new authoritative
path. Scripts that bypass the aggregator (manual `local://`
fabrication, ad-hoc JSON edits) now fail closed.
