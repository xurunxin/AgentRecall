## Why

The current Vitest setup installs a proxy that catches
`[vitest-worker]: Timeout calling ...` heartbeat rejections
and resolves them silently. Even if the timeout originates in
vitest infrastructure (not an assertion failure), swallowing
a release-run unhandled rejection conflicts with the
fail-closed Gate contract and makes runner instability hard
to distinguish from a valid green result.

The audit identified five concrete contract violations
(reproduced from `sub-issue #36` Required Changes):

1. The heartbeat-filter proxy is imported across release-critical
   jobs. Every vitest worker timeout is silenced.
2. Heavyweight suites are not isolated:
   - normal unit/integration tests
   - MCP black-box tests
   - migration/backup/import tests
   - multi-process stress
   - extracted-artifact lifecycle
   are all forced into a single Vitest invocation; a failure
   in any one blocks the others and timing is shared.
3. The least invasive stability fix is not evaluated.
4. Unhandled rejections, worker exits, task-update timeouts,
   child-process leaks, test skips are not all release-failures.
5. The 10,000-op stress test runs once per cleanup / full-suite
   invocation, not just once per intended release job.

Plus: cleanup + diagnostic artifacts are not preserved on
failure (they're discarded), and the final job topology +
expected durations are undocumented.

## Out of scope

- Release evidence fail-closed (covered by #34 / B1, parallel).
- Tag/version reproducible publication (covered by #35 / AB).
- New dependencies. Vitest + Node 24 stdlib only.
- A complete rewrite of the existing `test/multi-process-stress.test.ts`
  suite; this lane only changes the orchestration around it.

| `scripts/synthesize-vitest-failures.mjs` | NEW. The synthetic-rejection / synthetic-timeout injector: spawns a vitest worker with an injected `process.on('unhandledRejection', ...)` that emits a real rejection or real timeout, then asserts the orchestrator fails the run on the first synthetic event. |

| `test/release-gate/v113-stress-once.test.ts` | NEW. Asserts the 10k-op stress suite runs once when invoked from `scripts/run-test-suites.mjs`, NOT on every unrelated cleanup / full-suite invocation. Uses the test counter + the orchestrator's job-id pinning. |

### Behavioural contract

**Per-suite job in CI:**

| Suite | Vitest config | Worker pool | Isolation |
|-------|---------------|-------------|-----------|
| unit-integration | `vitest.config.ts` (default) | per-file pool (existing) | default |
| mcp-blackbox | `vitest.blackbox.config.ts` | `forks` single-fork | serial; 0 setup files |
| migrations | `vitest.migrations.config.ts` | `forks` single-fork | serial |
| stress | `vitest.stress.config.ts` | `threads` 8 threads | timeout 300s; `unhandled_rejections` → fail |
| packaged-artifact | `vitest.packaged-artifact.config.ts` | `forks` single-fork | serial |

**Deterministic invariants:**

- Each suite is a separate CI job that gates independently. A
  failure in one does not block another.
- `process.on('unhandledRejection', ...)` logs the rejection AND
  in release mode throws to fail the worker.
- `process.on('uncaughtException', ...)` logs and re-emits.
- Vitest worker timeouts (no `[vitest-worker]` exception
  eaten) → release failure.
- Child-process leaks (orphan temp dirs, orphan workers,
  leftover stdio handles) → release failure via the
  orchestrator's `cleanup_status` field.
- Test skips (`it.skip` / `describe.skip` in release-critical
  suites) → release failure.
- The 10k-op stress runs exactly once per release job,
  pinned via the orchestrator's job-id table.

**Aggregator contract:**

The aggregator's `test_summary` gains an
`unhandled_rejections` field per suite:

```ts
test_summary: {
  passed: number; failed: number; skipped: number; filtered: number;
  totals_from: "actual";
  suites: {
    unit_integration: { passed, failed, skipped, unhandled_rejections, worker_timeouts };
    mcp_blackbox: { same shape };
    migrations: { same shape };
    stress: { same shape };
    packaged_artifact: { same shape };
  };
}
```

A non-zero count in any field → release failure.

### Regression risk

The release-test topology changes. Tests at risk:

- `test/multi-process-stress.test.ts` — re-platformed under
  `vitest.stress.config.ts`. The test body itself is preserved
  (per the Out-of-scope).
- `test/blackbox/mcp-*.test.ts` — re-platformed under
  `vitest.blackbox.config.ts`. Test bodies preserved.
- `test/release-gate/p3-extracted-artifact-lifecycle.test.ts`
  — re-platformed under
  `vitest.packaged-artifact.config.ts`. Test body preserved.
- `npm run verify:artifacts` — runs the new suites; the
  verifier must still pass.

```text
## [1.1.3] — v1.1.3 GATE-06: heartbeat suppression removed + deterministic test orchestration (issue #36)

### Changed

- The heartbeat-filter proxy (`test/setup/heartbeat-filter.ts`)
  is REMOVED. Release-critical jobs no longer eat
  `[vitest-worker]` timeouts.
- `npm test` runs only the default config (unit / integration).
  Heavyweight suites are independent scripts under
  `npm run test:<suite>` driven by `scripts/run-test-suites.mjs`.

  suite) plus an aggregate job. A failure in any one suite
  blocks only that suite.
- `unhandled rejections`, `worker timeouts`, `test skips`,
  `child-process leaks` are now release-failures.

### Added

- 4 new `vitest.<suite>.config.ts` files (blackbox /
  migrations / stress / packaged-artifact).
- `vitest.setup.ts` — minimal unhandled-rejection logging +
  release-mode throw.
- `scripts/run-test-suites.mjs` — the deterministic
  orchestrator.
- `docs/adr/0008-deterministic-orchestration.md` + operator
  topology guide.
- 2 new test files.

### Removed

- `test/setup/heartbeat-filter.ts`.
```
