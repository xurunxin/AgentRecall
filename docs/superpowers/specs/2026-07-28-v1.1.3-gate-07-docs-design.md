## Why

Phase A + B merged six release-gate contracts (id / capability /
sensitivity / evidence / deterministic / tag-version) into `main`:
- `#31` identity: `lookup` / `strict_existing` / `register` modes
- `#32` capability: profile-scoped + load-time permission validation
- `#33` sensitivity: single canonical `AuthorizationDecision`
- `#34` evidence: fail-closed + canonical platform vocabulary
- `#36` deterministic: 5 segregated suite jobs + orchestrator + synthetic-failure smoke

The current README + operator docs predate Phase A + B. They
describe the v1.1.2 surface (`actorMaxSensitivity` string, no
profile context, legacy `updateEntry` access-by semantics, no
canon-platform evidence path). The CHANGELOG v1.1.3 section
already exists in the merged main, but the operator-facing
README still describes the v1.1.2 contract.

This lane (#37) aligns the public-facing documentation with the
verified v1.1.3 behavior. The behaviour is fixed; only the docs
move.

## Out of scope

- New schema. Type definitions are part of the Phase A source.
- Behaviour changes. Docs-only lane.
- New dependencies.
- Release publication. That's #38 / C2.

### Behavioural contract

The documentation tests pin:

1. Every shell command in `README.md` is either:
   - syntax-validated (regex check, optional), OR
   - executed end-to-end in CI against the project root.
2. The distribution contract is intact:
   - `files` array in `package.json` includes `dist`, `README.md`, `LICENSE`, `CHANGELOG.md`.
   - `LICENSE` file exists at the project root.
   - `dist/src/index.js` exists after `npm run build`.
   - `dist/bin/agent-recall.js` exists after `npm run build`.
   - The CLI `agent-recall --version` outputs `1.1.3`.
   - The server-version (`src/server-version.ts`) exports `1.1.3`.
3. The README references the v1.1.3 ADRs + guides correctly.
4. The README uses the canonical platform vocabulary everywhere (no `windows-x64`).
5. The README has no claims that contradict the v1.1.3 behavior
   (e.g., no "lookup mode may create a new identity" — that was
   the v1.1.2 bug #31 closed).

### Tests + TDD ordering

1. **RED** — `v113-documentation.test.ts` with the
   documentation tests as listed above.
2. **GREEN** — rewrite the README + cross-link the ADRs / guides.
3. **RED+GREEN** — `v113-distribution-contract.test.ts` with
   the distribution contract.
4. **CI wiring** — ensure `npm test` includes the new test
   files (the new test files are picked up by the default vitest config + the existing per-suite configs).
5. **Final** — `npm test` + typecheck + build + verify:artifacts.

### Regression risk

The README rewrite is a docs-only change. Risk:

- External links may break.
- A bad example that runs in CI but is wrong would surface a test failure.
- The documentation tests must not introduce flaky tests.

The AGENTS.md rule "改一处就补一类测" applies: every example that
runs in CI must be correct.
