## Lane-local deviation from the design spec

The design spec mandates the lane invoke
`scripts/prepare-release.mjs` (the v1.1.3 GATE-04 canonical
publication tool, merged in #34) to create the tag. The tool's
`createAnnotatedTag` function shells:

```text
git tag -a <RELEASE_TAG> -F <tag-message> --author=<author>
```

`git tag` has no `--author` option on standard Git (the option is
`git commit`-only — verified locally with `git tag --help` on Git
2.55.0). The prepare-release.mjs script's `git tag --author=...`
invocation exits 1 with `unknown option 'author=...'` on every
supported Git version. Calling the script with `DRY_RUN=0` therefore
fails closed before the tag is written.

The design spec's prose describes the canonical mechanism
("Uses `git tag -a v1.1.3 <release_commit> -m <message>` with a
temporary author/committer environment" — i.e. `GIT_AUTHOR_NAME` /
`GIT_AUTHOR_EMAIL` / `GIT_COMMITTER_NAME` / `GIT_COMMITTER_EMAIL`
env vars). The lane uses that mechanism instead:

1. The tag message is identical to the message `createAnnotatedTag`
   writes (the same four lines: tag name + release_commit +
   release_workflow + ISO date).
2. The tag is created with `git -c user.name=... -c user.email=...
   tag -a v1.1.3 366bc98 -F <tag-message>` so the global
   `~/.gitconfig` is NOT mutated (the `-c` flags set the values for
   this single invocation only).
3. The script's `validateEvidence` exit-0 chain runs first
   (`DRY_RUN=1` to a detached worktree at `366bc98`, with the
   canonical release-evidence.json + the verified `release-candidate.json`).
4. The v1.1.3 evidence file + the synthetic-good / synthetic-bad
   round trip prove the verifier accepts + rejects the document,
   matching the tool's `validateEvidence` invariant.

A follow-up to either:

- Patch `prepare-release.mjs` to use the env-var mechanism
  (`GIT_AUTHOR_NAME` + `GIT_AUTHOR_EMAIL` + `GIT_COMMITTER_NAME` +
  `GIT_COMMITTER_EMAIL`) instead of the unsupported
  `--author=...` flag, OR
- Document the canonical `git tag` mechanism in `docs/guides/release-publication.md`

is **outside this lane's scope** (the lane is gated on "no source
changes"). The post-release `v1.1.2` follow-up can pick up the fix.

The reported tag metadata above is what the operator will see on the
GitHub Releases UI after `git push origin v1.1.3`. The local commit
+ the local tag are immutable from this lane onward; no further
changes are made to the tag content.
