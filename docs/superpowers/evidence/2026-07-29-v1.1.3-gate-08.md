- **Migrations**: schema versions `v0` through `v13` all green. The

  suite cover the same surface.

## Known non-blocking limits

- `p3-extracted-artifact-lifecycle.test.ts` has one pre-existing failure
  unrelated to GATE-08: the suite asserts `release-artifact-hashes-`
  (with a trailing dash) in `release-candidate.yml`, but the workflow uses
  `release-artifact-hashes.json` (no trailing dash before `.json`). The
  regex was tightened in Phase A and the workflow was never patched. The
  failure is documented as a follow-up regression signal; the test is
  excluded from the v1.1.3 release lane on the project's exclusion list.
- The Windows-only `multi-process-stress` orphan-dir flake (the cleanup
  `rmSync` races the next test's `mkdtempSync`) is documented in the
  CHANGELOG as a pre-existing known non-blocking limit and remains on
  the exclusion list.
- The vitest worker `Timeout calling "onTaskUpdate"` warnings on Windows
  are reported by the harness after the test run has completed (exit 0
  on the test result counts); they are harness-level event-loop timing
  warnings, not test failures. The project's documented approach is to
  exclude the heavy multi-process stress from the monolith; the
  CI matrix leg is the authoritative surface.
- Windows PowerShell `Expand-Archive` dependency (the matrix leg shells
  `powershell -NoProfile -Command Expand-Archive` for the `.zip` archive).
  The Windows runner ships PowerShell; a future minimised runner image
  without PowerShell would need a Node-native fallback.
