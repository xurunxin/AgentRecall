## Per-commit detail

### Commit 1 — `AuthorizationDecision` + `resolveAuthorization`

```text
src/services/auth-context.ts (NEW)
```

The module exports:

```ts
export type AuthorizationDecision = {
  max_sensitivity: "normal" | "private" | "restricted";
  capability_token_present: boolean;
  reasoning: string;  // stable, loggable, never includes token bytes
};

export type AuthContextShape = {
  activeProfile: "core" | "extended" | "admin";
  hasCapability: boolean;        // process-level capability loaded?
  requestCapability?: string;    // per-request token (input only; never logged)
  capabilityType?: string;       // per-call capability type label
};

export function resolveAuthorization(
  ctx: AuthContextShape,
  operation: { kind: "read" | "write" | "maintenance" | "export" | "import"; restrictedAllowed: boolean }
): AuthorizationDecision;
```

The resolver:
- Default is `max_sensitivity = "normal"` (the SQL-boundary
  fail-closed default).
- `ctx.activeProfile === "admin"` AND `ctx.hasCapability` →
  `"restricted"` (after the #32 contract).
- `ctx.requestCapability` AND authorized by `CapabilityStore.authorize(...,
  ctx.activeProfile)` AND the capability type matches → `"restricted"`
  (per-request override).
- The decision is the single source of truth; downstream code
  never reads `actorMaxSensitivity` as a separate string.

### Commit 2 — Read service threading

```text
src/services/memory-read-service.ts (MODIFIED)
src/services/memory-service-helpers.ts (MODIFIED, minimal — type exports)
```

`MemoryReadService.ctx` gains an `authorization: AuthorizationDecision`
field. The constructor sets it from `(activeProfile, hasCapability,
profile)` via `resolveAuthorization(...)`. Every read method uses
`peekEntry(id, { maxSensitivity: ctx.authorization.max_sensitivity })`
or the SQL-boundary equivalent in `listEntries` / `searchEntries`.
A new `peekEntryUnrestricted(id)` overload is restricted to internal
authorized paths.

### Commit 3 — Maintenance classification

```text
src/services/memory-maintenance-service.ts (MODIFIED)
```

Every helper consults the decision before reading; the 12 actions
are classified per the spec table. `applyMergeDuplicates` on a
restricted merge requires the per-request capability token AND
logs the actor + reason. `applyForceForget` rejects without the
`sensitivity_restricted` capability.

### Commit 4 — Write + provenance

```text
src/services/memory-write-service.ts (MODIFIED)
src/services/provenance.ts (MODIFIED)
```

Internal CAS uses `peekEntryUnrestricted` only when
`ctx.activeProfile === "admin"` AND `ctx.hasCapability`. The public
write path uses the canonical decision. `explainProvenance` filters
restricted + private edges from unauthorized callers (the response
shape preserves the IDs but the `memory` and `relation` nodes are
omitted).
