## Per-commit detail

### Commit 1 — Evidence capture

The fixer's task spec includes the live release work. The order:

1. **Build**: `npm run build` — produces `dist/src/index.js` + `dist/bin/agent-recall.js` (the canonical entry paths from #37).
2. **Playwright**: invoke `npx playwright --version` to confirm the runner has the toolchain (optional; not required for non-Playwright lanes).
3. **Test (Core)**: `npm test --exclude '**/multi-process-stress.test.ts' --exclude '**/p3-release-immutability.test.ts' --exclude '**/p3-extracted-artifact-lifecycle.test.ts'` — must pass with 0 failures (excluding the pre-existing flakes).
4. **Test (Admin)**: `AGENT_RECALL_PROFILE=admin npm test ...` — must pass with 0 failures.
5. **Test (Extended)**: `AGENT_RECALL_PROFILE=extended npm test ...` — must pass with 0 failures.
6. **Pack the per-platform archives**: build 3 archives (one per platform) via `scripts/extract-release-artifact.mjs` (POSIX + Windows). The lane names them `agent-recall-1.1.3-{linux-x64,darwin-x64,win32-x64}.{tar.gz,zip}`.
7. **Compute hashes**: `scripts/compute-artifact-hashes.mjs` writes `release-artifact-hashes.json` with the shape `{linux-x64: {sha256, size_bytes, path}, ...}`.
8. **Verify packaged lifecycle**: `test/blackbox/packaged-install.test.ts` runs against each extracted archive (Core profile); the Admin profile black-box runs against the admin-extracted archive.
9. **Stage 3 fragments**: write 3 v1.1.3 fragments (one per platform) into the layout the `--fragments` aggregator expects.
10. **Aggregator + verifier**: `scripts/release-evidence.mjs --fragments <dir> --output <file>` + `scripts/verify-release-evidence.mjs --stable --evidence <file>`. Both must exit 0.
11. **Final evidence**: write `docs/superpowers/evidence/2026-07-29-v1.1.3-gate-08.md` with the verifier exit codes, test counts per platform, artifact hashes, stress + migration summaries.

The commit message records the `release_commit` SHA (= `366bc98`) + the per-platform hashes + the verifier exit codes.

## Risk register (lane-local)

| Risk | Mitigation |
|------|-----------|
| The verifier fails on the synthetic document | The lane provides a synthetic-good JSON for the verifier; if the verifier exits 1, the fixer's task re-runs the aggregator + verifier with a corrected document. |
| The `v1.1.2` tag gets moved | The `scripts/prepare-release.mjs` tool refuses to move an existing tag. The lane does not use raw `git tag --force`. |
| The packaged lifecycle test fails on a platform | The lane runs the test against each platform archive. If it fails, the release is blocked + the lane emits a "release blocked" evidence. |
| The 10k-op stress test fails on a platform | `test/multi-process-stress.test.ts` is excluded from the targeted run (pre-existing Windows flake). The canonical stress coverage is the matrix leg in CI. |
| Real GitHub Actions links unavailable | The lane uses placeholder URLs in the `RELEASE_NOTES.md` description; the operator fills in the real URLs after the manual push. |

## Note on the lane's actual workflow

The lane is a local-operator rehearsal; the actual production
release is the operator's manual step:

1. The lane emits the `release-evidence.json` + `release-candidate.json` + `RELEASE_NOTES.md` + `release-artifact-hashes.json`.
2. The operator reviews the lane's evidence + the `RELEASE_NOTES.md`.
3. The operator (with the `release-cutter` role) runs `git push origin main && git push origin v1.1.3`.
4. The operator (with the `release-cutter` role) creates the GitHub Release with the `RELEASE_NOTES.md` body + the 3 platform artefacts.

The lane does NOT do the push. The lane does NOT create the
GH Release. The lane stops at the local tag + the closed issues.
