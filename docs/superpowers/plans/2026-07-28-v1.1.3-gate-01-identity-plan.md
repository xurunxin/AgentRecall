    - On `process.platform === "win32"`, mixed-case `C:\\Repo` and
      lower-case `c:\\repo` resolve to the same identity when the

      existing strict behaviour is preserved).
  - 2 × concurrent preflight / apply drift tests using
    `vi.spyOn(store, "getProjectIdentity")` to override the second
    call to return a different `canonical_path`.
  - 4 × preflight snapshot tests: `BEFORE` snapshot of all eight
    project-related tables, run `preflightImport` against an unknown
    project, assert `AFTER === BEFORE` row counts and the envelope is
    `identity_conflict`.

### Commit 2 — GREEN mode gating

```text
src/scope-resolver.ts (MODIFIED)
```

Concrete edits:

- `resolveMemoryScopeWithStore(input, store, recordedBy)` becomes
  `resolveMemoryScopeWithStore(input, store, recordedBy, mode)`.
- `ProjectIdentityResolver.resolve(input, mode)` forwards `mode` to
  the helper (already does, just unused).
- The store-aware block in `resolveMemoryScopeWithStore` becomes
  three explicit branches:
  - `mode === "lookup"`: pure read. Look up alias → identity; never
    upsert; never register. If unknown, return
    `project_identity_conflict` (alias found, wrong id) or a new
    `identity_status: "absent"` envelope (no alias, no identity).
  - `mode === "strict_existing"`: pure read. If unknown → return
    `project_identity_conflict`. Never upsert; never register.
  - `mode === "register"`: existing behaviour, but isolated. Idempotent
    on `(project_id, canonical_path)`. Alias idempotent on
    `alias_key`.
- The legacy store-less tail (lines 415–449 in current source) is
  removed from production paths. If a test relied on it, port the
  test to use a stub `SQLiteMemoryStore` and `mode === "register"`.
- Add `mode` to the function signature in the `.ts` file; the
  TypeScript compiler will flag every caller. Fix the three known
  callers (the function is currently called from two places;
  `mode` defaults to `"register"` to keep `resolveMemoryScope` —
  the legacy function — working without rewriting every legacy call
  site).

### Commit 5 — GREEN apply-time revalidation

```text
src/portability/importer.ts (MODIFIED)
```

Inside `applyImport`'s existing `service.store.transaction(...)`
block, after the existing revision + budget re-check, add:

```ts
// 3. Identity revalidation: every (project_id, project_path)
//    captured at preflight time must still resolve to the same
//    canonical_path at apply time. Drifted / missing bindings
//    throw 'identity_drift' and roll the batch back.
const drift: Array<{ project_id: string; expected_path: string; observed_path: string | "absent" }> = [];
for (const scope of plan.scopes ?? []) {
  const observed = resolver.resolve(
    { scope: "project", project_id: scope.project_id, project_path: scope.project_path },
    "strict_existing"
  );
  if (!observed.ok) {
    drift.push({ project_id: scope.project_id, expected_path: scope.project_path, observed_path: "absent" });
    continue;
  }
  if (observed.value.project_path !== scope.project_path) {
    drift.push({
      project_id: scope.project_id,
      expected_path: scope.project_path,
      observed_path: observed.value.project_path ?? "absent"
    });
  }
}
if (drift.length > 0) {
  throw new ApplyImportError("identity_drift", "identity binding drifted between preflight and apply", { drift });
}
```

`ApplyImportError` is the existing error envelope; `identity_drift`
is a new member added in commit 5. `plan.scopes` is a new optional
field on `ImportPlan` populated by `preflightImport` (commit 5 also
adds this field).

ADR contents:

- **Status**: Accepted (replaces v1.1.2's carve-out documented in
  the CHANGELOG under issue #21).
- **Context**: The bug + the v1.1.2 carve-out.
- **Decision**: Three modes; `register` is the only mutating mode;
  `lookup` and `strict_existing` are pure reads; apply transaction
  revalidates identity binding.
- **Consequences**: The canonical registration path is
  `configureProjectBudget` (write service) + `agent-recall project
  register <path>` (CLI). MCP has no public register tool. The legacy
  escape hatch `AGENT_RECALL_ALLOW_UNBOUND_PROJECT_ID=1` is
  preserved.

Operator guide:

- A short section on how to register a project (the only way to make
  `project_id`-only calls succeed in strict mode).
- A short section on the legacy escape hatch and when it is
  appropriate (only for one-off operator triage, never for production
  agent flows).
