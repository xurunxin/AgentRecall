## Per-commit detail

### Commit 1 — RED scaffold

`v113-deterministic-orchestration.test.ts` (NEW) covers:
1. `npm run test:unit` runs only unit / integration
2. `npm run test:blackbox` runs only the MCP black-box suite
3. `npm run test:migrations` runs only the migration / backup / import suite
4. `npm run test:stress` runs only the multi-process stress suite
5. `npm run test:packaged-artifact` runs only the extracted-artifact suite
6. `npm run test:all-suites` runs every suite in isolation and aggregates JUnit
7. Synthetic unhandled rejection → orchestrator fails with code `UNHANDLED_REJECTION`
8. Synthetic vitest worker timeout → orchestrator fails with code `WORKER_TIMEOUT`
9. Cleanup artifacts preserved on failure
10. JUnit fragments uploaded per suite
11. Aggregator `test_summary.suites.<name>.unhandled_rejections` reflected
12. No release-critical `it.skip` / `describe.skip` in any of the 5 suites
13. The 10k-op stress runs exactly once per release job (pinned via `JOB_ID` env)

`v113-stress-once.test.ts` (NEW) covers:
1. Stress counter increments by exactly 1 across a single
   orchestrator run
2. The counter does NOT increment when running `test:unit`
   in isolation (proves the 10k-op stress doesn't sneak in)
3. The counter does NOT increment when running cleanup
   scripts

### Commit 3 — Delete heartbeat-filter + add minimal vitest.setup.ts

```text
test/setup/heartbeat-filter.ts (DELETED)
vitest.setup.ts (NEW — minimal)
```

`vitest.setup.ts`:
- `process.on('unhandledRejection', (reason) => { ... })`: log the
  rejection; in release mode (`AGENT_RECALL_RELEASE_MODE=1`),
  throw to fail the worker.
- `process.on('uncaughtException', (err) => { ... })`: log + re-emit.
- `process.on('exit', () => { cleanupTempDirs() })`: best-effort
  cleanup; preserved artifacts are NOT removed.

The intent: heartbeat rejections are no longer eaten; they fail
the run.

### Commit 4 — Orchestrator

```text
scripts/run-test-suites.mjs (NEW)
```

Implementation:
- Runs each suite as a separate `child_process.spawn('npm', ['run',
  'test:<suite>'], { env: { ...process.env,
  AGENT_RECALL_RELEASE_MODE: '1', JOB_ID: '<run-id>' } })`.
- Captures stdout + stderr + JUnit + cleanup_status.
- Preserves ALL of the above on failure.
- Aggregates JUnit into a single output.

### Commit 5 — Synthetic-failure injector


Implementation: spawns a vitest worker with an injected
`process.on('unhandledRejection', ...)` that emits a real
rejection or real timeout. The synthetic event must propagate
to the worker + to the orchestrator.

Tests in the RED scaffold assert the orchestrator fails on
the first synthetic event.

## Risk register (lane-local)

| Risk | Mitigation |
|------|-----------|
| `vitest.*.config.ts` excludes a test that should be in a suite | Manual cross-check against `test/**/*.test.ts`; the orchestrator's JUnit output confirms which tests ran. |
| `process.on('unhandledRejection')` escalates false positives | The handler distinguishes `Error` rejections from `{reason: 'testSkip'}` synthetic events; only real rejections throw in release mode. |
| Matrix job timeout on stress | The `release-stress` matrix is `pool: 'threads' maxThreads: 8 timeout: 300s`; if 300s is insufficient, #35 + #38 will catch it. |
| CI job topology changes break the existing release-candidate | `release.yml` (tag-only) is unchanged; the matrix + aggregate topology is additive. |
