fix(maintenance): durable plan storage with CAS-protected apply

Stage 15 PR-M0-4 (issue #3, spec § 6.2).

The pre-v6 maintenance plan/apply workflow had four
correctness gaps called out in the issue body:

  1. `extractDuplicateGroups` read fields the
     `find_duplicates` result did not expose
     (`kind`, `revisions`, `representative_title`),
     so the plan's `proposed_actions` was always
     empty and apply did nothing.
  2. The plan's `risk` was always "low" even for
     destructive actions.
  3. `apply_maintenance` re-ran the broad
     `merge_duplicates` action over the whole
     scope, so it could mutate entries that were
     not in the plan.
  4. The plan lived in a process-local Map and
     was lost on every MCP restart.

This PR fixes all four:

  - **Schema v5 → v6**: `maintenance_plans` +
    `maintenance_plan_items` tables; plan is now
    durable across MCP restart.
  - **`MaintenancePlanStore` rewrite**: thin
    wrapper over `SQLiteMemoryStore`; removes the
    process-local Map; new public shape
    `MaintenancePlanAction` (per-item, with
    `expected_revision` and `risk`); new
    `validate` method re-reads the on-disk items,
    re-computes the SHA-256 `plan_hash`, and
    returns one of `plan_not_found` /
    `plan_expired` / `plan_completed` /
    `plan_hash_drift` / `stale_revision` /
    `idempotency_mismatch` / `unplanned_target`.
  - **`plan_hash` tamper detection**: SHA-256
    over the canonical JSON of the items array.
  - **`mergePlannedGroup` / `forgetPlannedEntries`**
    helpers in `MemoryMaintenanceService`: each
    takes a fixed `target_ids` list from the
    plan, re-validates every entry's
    `expected_revision` (CAS) inside the
    transaction, and refuses on drift.
  - **`applyMaintenance` rewrite**: groups items
    by `evidence.fingerprint`, calls
    `mergePlannedGroup` per group, writes an
    `apply_maintenance` audit event, and marks
    the plan `completed` only on full success.
    A stranger entry (in the scope but not in
    the plan) is never touched.
  - **State machine**: `pending → completed |
    rejected | expired`. `rejected` is reserved
    for correctness failures (stale revision,
    hash drift, unplanned target); lifecycle
    failures (`plan_expired`, `plan_completed`,
    `plan_not_found`) do not overwrite the
    terminal state.
  - **Risk computation**: destructive items
    (merge / supersede / forget) carry
    `risk: "high"`; advisory items (retain)
    carry `risk: "low"`. Plan-level risk is
    `high` iff any item is destructive.
  - **Plan-item dedupe by target**: when the
    same memory appears in multiple duplicate
    groups (e.g. a pair sharing both title
    AND body), the most specific group's
    action wins (priority: merge > supersede >
    forget > update > retain).
