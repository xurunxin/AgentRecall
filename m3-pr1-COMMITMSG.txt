feat(intelligence): memory hierarchy (core/working/archival) + benchmark

Stage 15 PR-M3-1 (issue #9, spec § 6.5).

Pre-PR-M3-1 had a single "all memories are equal"
model. The new model has a 3-tier hierarchy:

  - `core`     — pinned, high-value, weighted × 1.3
  - `working`  — current tasks, weighted × 1.0
  - `archival` — historical knowledge, weighted × 0.7

This PR implements the hierarchy:

  - **Schema v9 → v10**:
    - `memory_entries.tier` column
      (`'core' | 'working' | 'archival'`, default
      `'working'`).
    - `memory_entries.valid_from` /
      `valid_until` (ISO 8601) for temporal
      validity.
    - `memory_episodes` table for
      episode-shaped memories.
  - **`MemoryEntry` extended** with
    `tier: "core" | "working" | "archival"`
    (required), `valid_from?: string`,
    `valid_until?: string`.
  - **Ranker tier weight**: the ranker reads
    `entry.tier` and applies a weight. The
    weight contributes to the linear score
    combination as a separate `tier_priority`
    component so the explain output is
    transparent.
  - **Build helper updated**: `buildEntry` reads
    `input.tier` (default `'working'`).
  - **Benchmark fixture**: 5 entries across
    2 projects, top-1 is `core`, bottom-1 is
    `archival`. The benchmark-style test
    proves the ranker weights the hierarchy
    correctly.
